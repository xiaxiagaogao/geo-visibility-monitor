## 1. 对标原则

| 从 g1geo **借鉴** | 我们 **明确不做（MVP）** |
|-------------------|---------------------------|
| 「先选平台 → 再看品牌监测结果」的路径感 | 一站式内容生成 / 优化建议 Agent |
| 总览数字墙 + 趋势复盘的报告感 | 多租户 SaaS、获客落地页、付费转化 |
| 多平台作为 **筛选维度**（UI 上预留） | 上线全部平台（当前仅 DeepSeek 有数据） |
| 提及追踪 → 可下钻证据 | 黑盒分数不可审计 |
| 案例/报告式分区（概览 → 明细） | PDF 周报、对外分享链路（后置） |

**一句话：** 页面**长得像监测台**，数据**算我们的 L2/L3**，风格**自己定**。

## 2. 全局版式（Layout）

参考 g1geo 类 B 端监测产品的常见骨架，结合我们已有 `/qa` 深色运维风，**正式前端建议：**

```text
┌──────────────────────────────────────────────────────────┐
│ Topbar：Logo/项目名 · 主品牌切换 · 平台筛选 · 时间范围 · 链到 /qa │
├────────────┬─────────────────────────────────────────────┤
│ Sidebar    │  Main                                       │
│  总览      │  页标题 + 筛选条                              │
│  回答明细  │  内容区（KPI / 表 / 图 / 详情）                 │
│  抓取任务  │                                             │
│  ────────  │                                             │
│  运维质检↗ │  （外链现有 :8200/qa，不重复造 B7）            │
└────────────┴─────────────────────────────────────────────┘
```

| 区域 | 需求 |
|------|------|
| Topbar | 固定；展示当前 `brand_id` 名称（默认土巴兔）；`platform` 多选/单选（无数据平台 **disabled +「未接入」**）；`from/to` 可选（MVP 可先「全部」） |
| Sidebar | 3 个主入口足够（总览 / 回答 / 任务）；不要一上来做 8 个商用菜单 |
| 主区 | 卡片化分区，留白适中；空状态文案诚实（如「本品提及率 0%，样本 n=11」） |
| 主题 | **自定**：推荐深色监测风（与 QA 接近）或浅色报告风二选一，F0 定一种并写进 tokens |

**平台筛选（g1geo 能力边界在 UI 上的投影）：**

| 平台 chip | MVP 状态 |
|-----------|----------|
| DeepSeek | 可用，有数据 |
| 豆包 / Kimi / 通义 / … | **灰显「后续接入」**，点击 toast 或禁用，避免假选项 |

## 3. 页面清单与改动说明

相对 [21](./21-l3-frontend-plan.md) 原 MVP 三页：**结构保留，版式与模块按 g1geo「监测台」加细。**

### 3.1 总览 `/`（主对标：监测首页 / 增长报告头图）

**目标：** 一眼看到「被 AI 提到了没有、和竞品比怎样、趋势如何」。

| 模块 | 需求 | 数据 |
|------|------|------|
| 筛选条 | 平台、时间、是否仅 `deepseek_web`（高级可折叠） | query → counts |
| KPI 行（4 卡） | ① 有效样本 n_valid ② 本品提及率 ③ 本品命中数 m ④ SoV(本品) | L3(rates) ← counts |
| 次级 KPI（可选一行） | 头部提及占比 m_head/m_mentioned；error 样本数（质量） | counts denominator + brand |
| 趋势 | 按日：n_valid、提及率（双轴或双图） | `group_by=day` |
| 竞品条/柱 | 本品 vs 竞品 m_mentioned 对比 | brand + competitors |
| 快捷入口 | 「查看回答明细」「发起一次抓取」 | 路由 |

**空/零状态：** 提及率 0 时仍显示 0% + 说明「当前有效样本中未命中别名」，禁止显示假繁荣。

**不做：** 大字营销 slogan、咨询二维码、内容优化建议卡片。

---

### 3.2 回答明细 `/responses`（主对标：提及追踪列表）

| 模块 | 需求 |
|------|------|
| 筛选 | platform、answer_status、prompt、关键词（MVP 可先 status+platform） |
| 表格列 | id、时间、platform、source、answer_status、本品是否提到、截图有无、latency |
| 行操作 | 进入详情 |
| 批量 | MVP 不做 |

列表视觉：紧凑表 + status 徽章（ok/error），接近 g1geo「可持续监测」清单感，而不是博客列表。

---

### 3.3 回答详情 `/responses/:id`（主对标：单次对话证据 / 可审计）

| 模块 | 需求 |
|------|------|
| 元信息 | platform、prompt、时间、job_id、source、latency |
| L1 条 | answer_status、各品牌 mentioned / type / position / evidence_snippet |
| 正文 | full_text 可读排版（markdown 粗渲即可） |
| 证据 | 截图预览（大图、可新标签打开）；**不展示 DeepSeek 会话 URL** |
| 引用 | citations 表；空则显示「本样本无解析到引用」 |

---

### 3.4 抓取任务 `/jobs`（主对标：检测任务，不是营销「免费检测」落地页）

| 模块 | 需求 |
|------|------|
| 创建条 | prompt 下拉、platform=deepseek、samples=1..n、提交 |
| 列表 | id、status、platform、时间、error_message、链到 response（若有） |
| 反馈 | pending/running/success/failed 徽章；失败展示 error |

**不做：** 未登录免费检测弹窗、多平台一键全选（无 Provider 时禁止假装可跑）。

---

### 3.5 后置页面（写入需求但 **L3 第一期不做**）

| 页面 | g1geo 对应感 | 我们何时做 |
|------|----------------|------------|
| 品牌/别名/竞品设置 | 后台配置 | A2，L3 后 |
| 多平台对比报告 | 全平台检测报告 | 第二平台后 |
| 引用来源专题分析 | 引用分析 | citations 质量够后 |
| 对外案例报告页 | /cases | Out / 很后 |

## 4. 与 docs/21 的差异（本次要改动的点）

| 项 | 原 21 方案 | 本次调整 |
|----|------------|----------|
| 对标 | 多开源拼盘 | **主对标 g1geo 的监测/平台/报告 IA**；开源仅辅 |
| 布局 | 未写死 shell | **Topbar + Sidebar + 主区** 写死为默认 |
| 平台 | 提到筛选 | **Chip 展示多平台，仅 DeepSeek 可点** |
| 总览 | KPI+趋势 | 明确 **4 KPI + 竞品柱 + 趋势 + 零状态文案** |
| 详情 | 全文+截图 | 明确 **L1 条 + 禁会话 URL + 引用空态** |
| 风格 | 未定 | **自定 tokens；推荐深色监测风** |
| 设置页 | 后置 | 维持后置（与 g1geo 完整后台不对齐） |

**结论：** 前端页面需求 **需要补这一份（23）**；21 的步骤 F0–F5 仍适用，实施时以 **21 步骤 + 23 版式** 为准。

## 5. 交互与文案细则（MVP）

1. 所有比率保留 1 位小数百分比；n_valid=0 显示 `—`。  
2. 筛选变更 → 重新请求 counts / 列表，不前端假算历史。  
3. 加载：骨架屏或 spinner；错误：展示 API `detail`。  
4. 中文 UI；数字用等宽或 tabular。  
5. 顶栏可放「数据口径：L2 counts · 假数据已排除」小字，增强可信度（对齐 g1geo「可复盘」叙事，用我们的实现）。
