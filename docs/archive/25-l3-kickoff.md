### 1.1 T1 + T2 的组合推论：必须用静态导出

Next.js 要配 `output: 'export'`，产出纯静态文件给 geo-api 托管。
**代价：没有 SSR / 服务端组件 / 中间件**——对一个客户端取数的看板没有影响，
但写代码时不能用 `async` 服务端组件那套。

## 2. docs/21 §2 契约表已过期

那张表写在鉴权（[24](./24-code-review-fixes.md) §1.1）之前。现状：

| 路径 | 认证 |
|------|------|
| `/health` | 公开 |
| `/v1/*` | `X-API-Key` 请求头 |
| `/qa/*` | 额外接受 HttpOnly Cookie |

**浏览器 SPA 不能安全持有 API Key** —— 打包进去 F12 就能拿到，等于没鉴权。
而且截图证据要放进 `<img src>`，**`<img>` 发不了自定义请求头**，只能靠 Cookie。

因此 F0 需要在后端补一件事：

- 前端页面与 `GET /v1/*`、媒体路由 **接受 QA 那个 HttpOnly Cookie**
- **写接口（POST/PATCH/PUT/DELETE）仍然只认请求头** —— CSRF 防线不能破
  （已有测试 `test_security.py::test_v1_ignores_cookie` 守着）

登录入口复用 `/qa/login` 或做一个统一登录页，F0 时定。

## 3. 数据准备：让看板有东西可看

### 问题

13 条有效样本里，土巴兔 / 齐家网 / 住小帮 **一次都没出现**（SQL 直查确认）。
照这个状态做 F2，比率、SoV、竞品柱、位置分全是 0 或 —，**算错了也看不出来**。

### 做法

用 `app.scripts.brand_candidates` 统计「AI 实际点名了谁」，按出现样本数排序，
取 >= 3 条样本的真实品牌录为品牌 1 的竞品：

| 品牌 id | 名称 | 别名 |
|---------|------|------|
| 28 | 千州装饰 | — |
| 29 | 即梦装饰 | — |
| 30 | 匠云居装饰 | 匠云居 |
| 31 | 缘环装饰 | 上海缘环装饰 |
| 32 | 品筑时代装饰 | 品筑时代 |
| 33 | 星杰装饰 | 星杰国际设计、星杰 |

品牌 1 的竞品列表：`[2, 3, 28, 29, 30, 31, 32, 33]`（保留原有齐家网/住小帮）。
录完强制重跑 L1（新竞品需要生成 mention 行）。

> **口径说明：** 土巴兔是**装修平台**，千州/即梦等是**装修公司**，严格说不同品类。
> 但从 GEO 监测的角度，「问装修公司哪家好时谁占据了曝光」正是要衡量的东西，
> 计入 SoV 是合理的。若你认为该分开统计，改 `competitor_links` 即可，不影响代码。
