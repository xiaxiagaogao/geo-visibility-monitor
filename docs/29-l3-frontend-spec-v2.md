## 3. 逐页需求

### 3.1 总览 `/`

**这一页只有一个任务：让 60% 这个数字当场自我解释。**
60% 是「5 条满分 + 2 条挂零」平均出来的，不是稳定表现（docs/27 §6.1）。

**KPI 行（4 卡）** —— SoV 砍掉后腾出的位置给了「覆盖缺口」，因为后者可执行：

| # | 指标 | 口径 | 真实值 | 状态 |
|---|------|------|--------|------|
| 1 | 有效样本 | `answer_status=ok`，已排除假数据 | 35 · 35/35 全部有效 | ✅ |
| 2 | 本品提及率 | `m_mentioned / n_valid` | 60.0% · 21/35 | ✅ |
| 3 | **首位提及率** | 本品出场顺位为 1 的样本数 / 本品被提及样本数 | 待后端补 rank | 🟡 降级 |
| 4 | 覆盖缺口 | 本品缺席或明显落后、且竞品在场的提问数 | 5（2 完全 + 3 部分） | ✅ |

> **为什么不叫「首推率」**：GeoMonitor 叫首推率，暗示「被推荐为第一」。
> 我们的 rank 是**出场顺位**，只知道它第一个被提到，不知道是不是被推荐。
> 名字必须match口径，否则就是在用措辞夸大结论。

「头部位置占比」（`m_head / m_mentioned` = 15/21 = 71.4%）**不进 KPI 行**，
降为逐提问分布面板里的次级信息 —— 它和首位提及率含义相近（篇幅前 1/3 vs 顺位第 1），
两个都摆在顶上会互相稀释。

**内容区**（自上而下）：

1. **全宽** ·「60% 是两极平均出来的，不是稳定表现」
   逐提问 emphasis 横条，右侧同时给 `xx.x%` 和 `m / n`。挂零行用 danger 起始笔画 + 文字标注。
2. **左 3 / 右 2** ·「覆盖缺口 · 优先处理」前 3 条 ｜「最近采集批次」
   - 左：缺口清单前三条 + 「查看全部 →」。**这是本页唯一可执行的产出，必须在首屏。**
   - 右：按日期的批次卡，每行 日期 / 样本数 / 提及率 / 状态。
3. 品牌提及对比 emphasis 横条（本品 vs 7 个竞品）。

**明确不做**：GeoMonitor 工作台那种「让品牌直接成为 AI 的答案」营销首屏（docs/27 §12）。

### 3.2 采集批次 `/batches/`

批次 = **采集日期**。列表页直接进最新一批，用日期选择器切换。

**批次头卡**：`2026-08-02 · 安踏监测集` + `成功` 徽章 + `10 问题 × 3–5 样本 = 35 条` + 平台 chip。

**KPI 行（4 卡）**：本批的 有效样本 / 提及率 / 首位提及率 / 覆盖缺口。

**Tab**（GeoMonitor 是 检测详情/引用分析/检测报告，我们换第三个）：

| Tab | 内容 |
|-----|------|
| 命中矩阵 | 问题 × **品牌**（不是平台 —— 我们只有 DeepSeek） |
| 引用分析 | 本批的引用来源聚合 |
| 样本列表 | 逐条样本表，可下钻到原始回答 |

**命中矩阵格子四态** —— 沿用 GeoMonitor「绝不伪造名次」的四态思想，映射到我们的数据：

| 态 | 显示 | 触发 |
|----|------|------|
| 命中 · 有顺位 | `3/3` 主 + `#2` 副（该品牌在这几次样本里的**中位**出场顺位） | rank 已落库 |
| 命中 · 无顺位 | `3/3`，**不显示 #** | rank 未落库，或命中只在引用里（`mention_type=citation_only`） |
| 未命中 | 虚线空格 `—` | `mentioned=false` |
| **本品挂零** | 虚线 + `--danger` 描边 | 本品列且 m=0 —— 我们比 GeoMonitor 多的一态 |

> 第四态是我们特有的。本品缺席是这个产品的核心结论，不能和「某个竞品没出现」用同一个样式。

**小样本处理 —— 这里我不照搬 GeoMonitor。**
它的阈值是 `n<5` 挂 ⚠️。我们每条提问只跑 3–5 个样本，照搬会让 10 行里 8 行挂满警告图标，
警告一旦挂满就等于没有。改为：

- **页面级**说一次：「每条提问 3–5 次采样，比率的置信区间很宽，请按数量级读而非按小数点读」
- **行级**只在 `n < 3` 时标 ⚠️
- Wilson 区间放进格子的 hover tooltip，不占版面

### 3.3 覆盖缺口 `/gaps/`

**本品缺席或明显落后、竞品在场的提问清单，按优先级排序 → 直接喂给推流团队。**

这是我们唯一一页数据完全齐备、且输出可执行的页面。

| 列 | 说明 |
|----|------|
| 缺口提问 | 提问原文 |
| 类型 | `unprompted` / `scenario` |
| 缺口档 | **完全缺席**（本品 m=0）/ **明显落后**（本品命中率 < 最高竞品的一半） |
| 本品 | `0/5` 等，完全缺席用 danger 色 |
| 在场竞品 | 命中的竞品名 + 各自 `m/n` |
| 优先级 | 高 / 中 / 低 |

**优先级 = 失分量**：`Σ max(0, 竞品命中数 − 本品命中数)`
读作「这条提问下，竞品合计比本品多拿了多少次提及」。≥10 高 · 5–9 中 · <5 低。

> **初版写的是「在场竞品数 × 样本数」，那个公式是错的**，写单测时被逮到。
> 它把 1/3 的竞品和 3/3 的竞品算成一样重，于是「适合跑步新手」
> （6 个竞品各拿一点，本品 1/3 其实不算落后，得 18 分）会盖过
> 「2026年跑步鞋」（本品 0/5，三个竞品各 5/5 全线丢单，得 15 分）——
> 排序和常识相反。失分量还有个附带好处：**纯整数运算**，
> 不用先派生比率，正好贴合「后端只给 counts」。

按现有数据算出来是 5 条：

| 提问 | 档 | 本品 | 在场竞品 | 失分量 | 优先级 |
|------|----|------|---------|--------|--------|
| 2026年跑步鞋哪个品牌好？ | 完全缺席 | 0/5 | 耐克 5/5 · 阿迪达斯 5/5 · 亚瑟士 5/5 | **15** | 高 |
| 马拉松比赛穿什么跑鞋？ | 明显落后 | 1/3 | 耐克 3/3 · 阿迪达斯 3/3 · 亚瑟士 3/3 | 6 | 中 |
| 适合跑步新手的鞋怎么选？ | 明显落后 | 1/3 | 耐克 3/3 · 亚瑟士 3/3 · 阿迪达斯 2/3 · 李宁/特步/361度 各 1/3 | 5 | 中 |
| 健身房训练穿什么鞋合适？ | 完全缺席 | 0/3 | 耐克 3/3 · 阿迪达斯 1/3 | 4 | 低 |
| 大体重跑者穿什么跑鞋？ | 明显落后 | 1/3 | 361度 3/3 · 亚瑟士 3/3 · 李宁 1/3 | 4 | 低 |

同分时**完全缺席排在明显落后之前** —— 0 分比落后更该先处理。

> 「明显落后」这一档是我们对 GeoMonitor 的扩展 —— 它只定义了完全缺席。
> 但 1/3 对 3/3 同样是丢单，只做 0 分那一档会漏掉一半的可执行信息。

### 3.4 引用分析 `/citations/`

**KPI（3 卡）**：引用总数 / 来源数（按域名去重）/ 引用覆盖率（带引用的回答占比）。

**内容**：来源明细表 —— 排名 / 来源 / 覆盖提问数 / 引用次数 + 横条。

**砍掉 GeoMonitor 的「平台引用分布」环形图** —— 我们只有 DeepSeek，
一个平台的构成比是一根 100% 的条，画出来是在假装有多样性。

> ⚠️ 这一页能不能立起来，取决于真实引用量有多少（§10 待核实）。
> 若引用普遍为空，本页降级为空态并从侧栏隐藏，不做假图。

### 3.5 原始回答 `/responses/`

沿用 GeoMonitor 的**左 2 / 右 1** 分栏，这个布局很好，照搬。

**左栏**：
- 头：平台 badge · `run 1/3` · 时间 · 右上角 `已提及 · #2` 徽章
- 提问（heading）
- **L0 全文，命中处内联高亮**（品牌名 accent 底色）
- 引用来源卡片列表（favicon + 标题 + 域名）

**右栏**：
- 执行元数据：执行模式 / 耗时 / `answer_status` / 出场顺位 / 情感（暂无）/ **别名命中**（`瑞特 ×2 · RIGHTEST`）
- 回答截图（`/v1/media/screenshots/{basename}`，靠 Cookie 取）

**内联高亮与别名命中都依赖后端补 offset**（§5）。补之前：全文平铺渲染 + 一行说明，
**绝不**在前端按 matched_term 自己去正文里找 —— 那会和 L1 标注口径分叉（docs/27 §8 明令）。

**下钻入口与永久链接**：矩阵格子 / 列表行 → 打开本页；
静态导出下没有动态路由段，所以用 `/responses/?rid=29`（docs/28 §2.1，仍然有效）。

### 6.2 矩阵格顺序色阶（重新取的，已验证）

GeoMonitor 的热力图色阶是 浅灰 → 近黑 → 青绿，**亮度非单调**，
中段 `51` `58` `72` 几格是深色字压近黑底，数值根本读不出来。这是它最明显的一处缺陷，不能带过来。

改为单一 teal 色相、亮度单调的三档 ordinal 阶：

| 档 | 浅色模式 | 深色模式 |
|----|---------|---------|
| ≤33% | `#14B8A6` | `#0F766E` |
| 34–66% | `#0D9488` | `#2DD4BF` |
| ≥67% | `#115E59` | `#5EEAD4` |
| 未提及 | 无填充 + `--border` 虚线 | 同 |

> **两种模式的方向是相反的**，这不是笔误。判据是「离底色越远 = 值越大」，
> 不是绝对明暗：浅底上越深越远，深底上越亮越远。
> 若深色也照搬「越深越高」，最高档 `#0F766E` 会贴着 `#0A1120` 往后退，
> 反而是最弱的一档最扎眼 —— 实机渲染时就是这么错的，看图才发现。

验证结果（`validate_palette.js --ordinal`）：

```text
浅色 surface #FFFFFF ：亮度单调 PASS · 相邻 ΔL PASS · 浅端对底 2.49:1 PASS · 单一色相 6° PASS
深色 surface #111C2E ：亮度单调 PASS · 相邻 ΔL PASS · 浅端对底 3.12:1 PASS · 单一色相 5° PASS
```

**格内文字色必须分档定**（这就是 GeoMonitor 栽的地方，实测对比度）：

| 格底 | 白字 | 深墨字 `#0F1B2D` | 取哪个 |
|------|------|------------------|--------|
| `#14B8A6` | 2.49:1 ✗ | **6.94:1** ✓ | 深墨 |
| `#0D9488` | 3.74:1 ✗ | **4.62:1** ✓ | 深墨 |
| `#115E59` | **7.58:1** ✓ | 2.28:1 ✗ | 白 |
| `#0F766E`（深 · ≤33%） | **5.47** ✓ | 3.16 ✗ | 白 |
| `#2DD4BF`（深 · 34–66%） | 1.86 ✗ | **9.29** ✓ | 深墨 |
| `#5EEAD4`（深 · ≥67%） | 1.48 ✗ | **11.68** ✓ | 深墨 |

规律：**离底色最远的那一档用反色墨，另两档用深墨**。
浅色模式是最深档 `#115E59` 配白字，深色模式是最暗档 `#0F766E` 配白字。
格内数字 12–13px 属小字，按 4.5:1 判，六项全过。

### 6.3 emphasis 横条（本品 vs 竞品）

| | 本品 | 竞品 |
|---|------|------|
| 浅色 | `--accent` `#0D9488` | `#CBD5E1`（= `--border-strong`）|
| 深色 | `#2DD4BF` | `#4A5F85` |

实测分离度：

```text
浅色：ΔE 28.6（正常视觉）· 23.9（最差色觉类型）  PASS
深色：ΔE 33.0（正常视觉）· 30.7（最差色觉类型）  PASS
```

**一条硬规则：竞品条不许用 `#64748B`**（那个中性灰）。
实测它和 accent 在绿色盲下 ΔE 只有 5.3，正常视觉也才 11.0 —— 双双硬 FAIL。
它作为文字色没问题，作为**填充色**和 accent 撞。

两种模式的竞品填充对底色都低于 3:1（浅 1.4、深 2.7），验证器给 WARN 要求"补偿"。
我们的补偿是现成的：**每根条右侧都直接标了 `xx.x%` 和 `m / n`**，不依赖颜色读数。

### 6.4 两条继承自 docs/27 的硬约束（换成浅色后依然成立）

1. `--success / --warning / --danger` **只做徽章且必须配文字**，绝不当图表系列色。
2. 任何新增的顺序/分类色阶，**换底色就必须重跑验证器** —— 参考值绑定它自己的底色。

## 7. 组件规范

### 7.1 三态 —— 每个数据组件必备

照搬 GeoMonitor，写进组件而不是散在各页：

| 态 | 表现 |
|----|------|
| 加载 | Skeleton（shimmer），不用 spinner |
| 失败 | 图标 + 「加载失败」+ `接口 {status} · {code} · {message}` + 「重试」按钮 |
| 空 | 图标 + 「暂无数据 · 该时间范围未采集」|

**第四态是我们加的：降级**（§5.3）——「暂无排名数据」「暂无情感数据」。
它和「空」不同：空是没采到，降级是采到了但这个维度后端还没算。**文案必须区分**，
否则用户会以为是采集出了问题。

### 7.2 KPI 卡

结构：标签 + ⓘ口径提示 ／ 大数字（30/700）+ 环比 pill ／ **分母副文案**。

**分母副文案是强制的** —— docs/27 §5.3：凡出现比率，必须同时显示 `m / n`。
组件 props 强制要 `m` 和 `n`，**没有只收 rate 的重载**，让孤零零的百分比在类型层面写不出来。

**左侧彩色竖条只在异常时出现。** GeoMonitor 给四张卡配了绿/绿/橙/红四色竖条纯装饰，
破了它自己「全站同色 = 同义」的规矩 —— 「正面率」那根橙条会和 `--warning` 撞义。
我们改为：正常态统一 `--border`，只有需要警示的项（如覆盖缺口 > 0）才上 `--danger`。
这样红条一出现就有信息量。

### 7.3 矩阵单元格

四态见 §3.2。核心原则照搬 GeoMonitor 原话：
**「排名可能没有序号 → 已提及·未排名 必须和 未提及 视觉区分，绝不伪造名次」**。

### 7.4 FilterBar

平台多选 · 时间范围 · 品牌/竞品，选中值 ⇄ URL 双向同步，可分享可刷新保持。

**压成一行。** GeoMonitor 把「更多筛选」单独放第二行，那一行只有一个按钮，白占 44px 高度。
改为同一行右对齐。

## 8. 相对 GeoMonitor 的排版改动汇总

| # | 改动 | 理由 |
|---|------|------|
| 1 | 顺序色阶改为亮度单调的单一色相 | 原稿中段数值不可读（§6.2）|
| 2 | KPI 竖条只在异常时着色 | 原稿四色纯装饰，破坏「同色=同义」（§7.2）|
| 3 | FilterBar 压成一行 | 原稿第二行只有一个按钮 |
| 4 | 矩阵行高 68px → 44–48px，行首两行（提问 + 本品 m/n） | 我们 10 行 × 8 列，原密度一屏放不下 |
| 5 | 覆盖缺口从侧栏第 7 位提到第 3 位，并在总览首屏嵌前 3 条 | 这是唯一数据齐备且可执行的页 |
| 6 | 小样本 ⚠️ 从逐格改为页面级说明 + 仅 n<3 标行 | 我们 n=3–5，逐格挂会挂满，警告挂满等于没有 |
| 7 | 引用分析去掉平台环形图 | 单平台的构成比是一根 100% 的条 |
| 8 | 侧栏去掉分组标题 | 只剩一组，标题是噪音 |
| 9 | 「首推率」改名「首位提及率」 | 我们的 rank 是出场顺位，不是推荐名次，名字要 match 口径（§3.1）|

**保留不动的**：顶栏「只读」badge + 采集状态行；原始回答页左 2 / 右 1 分栏；
三态写进组件规范；筛选 ⇄ URL 同步；字阶与间距阶。

## 9. 技术栈与工程约束

沿用 docs/28，只列与本文相关的：

| 项 | 取值 |
|----|------|
| 框架 | Next.js（App Router）+ TypeScript strict |
| 构建 | 生产 `output:'export'` + `trailingSlash:true`；开发用 rewrites 代理到 VPS |
| 部署 | 静态产物由 geo-api 同源托管，仍走 8200 |
| 样式 | CSS Modules + `tokens.css`（浅/深两套用 `[data-theme]` 切） |
| 服务端状态 | TanStack Query，queryKey = URL 筛选状态 |
| 图表 | **不引图表库** —— 砍掉热力图/面积图/折线后，剩下的全是横条 + meter + 表格，手写 SVG/CSS 足够。等真有时序数据再评估 ECharts |
| 鉴权 | 读：Cookie `geo_qa_key`（只对 GET/HEAD/OPTIONS）；写：`X-API-Key` 头，key 存 sessionStorage |
| 详情永久链接 | `/responses/?rid=123`（静态导出无动态路由段）|

> GeoMonitor spec 里的 Vue 3 / Element Plus / ECharts / MSW / `?token=` 全部不采用。
> 尤其 `?token=` —— 它会把 key 打进前端包，spec 自己也写了「切勿用于公网」，
> 而我们就挂在公网 8200 上。
