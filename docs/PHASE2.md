## 1. 一个判断：第二个平台是这一阶段的分水岭

`app/providers/registry.py` 那层设计得好，加平台**确实只改一个文件**。
但前端这一轮所有口径都建立在「只有一个平台」这个隐含假设上，
第二个平台一接就会同时引爆四件事：

1. **「提及率 60%」跨平台是什么意思？**
   DeepSeek 80% + 豆包 20% 混算出 50%，对运营没有任何操作价值 ——
   他要知道的是「豆包上我不行」。`/v1/counts` 早就支持 `group_by=platform`，
   但前端一次都没用过。
2. **命中矩阵要变形。** 现在是 提问 × 品牌。加一维就是三维，而三维矩阵不可读 ——
   所以大概率结论是「平台是筛选器，不是维度」。这个决定影响 A6 整页版式。
3. **`apps/web/README.md` §5「平台环形图不做」的理由当场失效**
   （原因写的是「只有一个平台，画出来是假装有多样性」）。
4. **job 数翻倍**，`services/counts.py` 那个「拉 `full_text` 进 Python 再累加」
   的债会提前咬人。

还有一条容易漏的：**每个平台一份会过期的登录态。**
DeepSeek 用 `storage_state`。过期的表现是一批 job 全 `failed` ——
而这和「平台没接」「网络问题」的排查方向完全不同，现在没有任何东西能区分它们。

**所以顺序是：先定口径，再写 Provider。** 反过来做，Provider 写完前端也接不上。

#### P2-01 的收成：冒烟第一次跑就抓到一个已上线的 bug

`first_offset` 是 Python 的**码点**索引，而前端用 `String.slice` 按 **UTF-16
单元**切 —— 一个 🏃 在 Python 里算 1、在 JS 里算 2。含 emoji 的回答（DeepSeek
很常见）证据页高亮全部错位。

**线上没有画错** —— `buildHighlights` 那条自检拦住了：对不上就不画、改报告警。
但代价是那些回答一律没有高亮。修法见 `apps/web/src/lib/l3/text.ts`；
顺藤还摸到同类第二处（`isPreviewTruncated` 拿码点数比 UTF-16 长度）。

**`docs/API.md` §7.1 那条不变量的写法本身就是错的**（写成了
`full_text.slice(...)`），它正是误导的源头，已更正为分别给出 Python 与 JS 两种写法。

这条记在这里，是因为它回答了「为什么冒烟值得先做」——
它抓的不是「按钮点不动」，是**跨语言口径分叉**这种任何单层测试都看不见的东西。

#### P2-02 顺带补的后端一致性

做任务编辑时发现 **`start_run` 不检查 `task.is_active`** —— 「已停用」只是任务
列表里的一个徽章，而 `create_run` **是**按 `Prompt.is_active` 过滤提问词的。
同一个字段名一处当真、一处装饰。

之前不明显，因为界面上从没有停用任务的入口。编辑入口一做出来，
不补这条就等于在界面上写一句假话。已补：停用的任务发起运行返回 400
（不是 404 —— 任务确实存在、你也看得见，只是它被停用了）。

## 4. 待拍板的产品决策（不是技术任务）

这几项定不下来，对应的编码任务就不该开始。

| 决策 | 关键取舍 |
|---|---|
| **P2-05 多平台口径** | 混算 `Σm/Σn` / 强制分平台 / 平台当筛选器。**这是二阶段第一个真正的决策点**，它决定 A6 整页版式 |
| **开联网搜索重抓** | 能换来 `citations`（引用分析整页），但**会破坏与现有基线的可比性** —— 等于重开一条基线。好消息是 Run 实体让「新基线」这件事是可表达的（`run.note`） |
| **情感接哪个 LLM** | 成本、延迟、口径稳定性。接完 `sentiment` 才有值 |
| **多租户做到什么程度** | `workspace` 继续当裸整数，还是做成真实体（P2-22）。影响客户规模上限 |
| **删除 run / task 给不给接口** | 删 run 会**级联删掉证据**，历史结论跟着变。可能的答案是「只给归档，不给删」 |

## 5. 怎么用这份文档

1. **开工前先看 §4。** 如果这一项挂在某个未拍板的决策下面，先去把决策做掉。
2. **一项一个分支、一步一个 commit**，commit message 写清根因 / 改动 / 验收。
3. **完成后回来更新本文**：把该项标 ✅ 并写清落在哪个文件；如果实现过程中
   推翻了这里的判断，**改这里的判断**，别让它留着误导下一个人。
4. 现状类的结论（口径、结构、纪律）不写进本文 ——
   它们属于 `BACKEND.md` / `API.md` / `apps/web/README.md`。本文只管「接下来做什么」。
