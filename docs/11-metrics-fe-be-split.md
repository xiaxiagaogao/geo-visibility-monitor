# GEO 指标派生与前后端分工（v0.1 · 已拍板）

> 来源：用户整理的需求文档 v0.1（2026-07-30）  
> 仓库内为**对齐后的权威摘要 + 拍板结果**；细节原则与原文一致。

## 拍板

- 总开关：同意 v0.1  
- 命名 **1A**：L0–L3  
- L2 MVP **2B**：计数 API 优先，日物化后置  
- L1 字段：见 [10-data-responsibility](./10-data-responsibility.md)  
- 模块 **4A**：Python L1 + TS L3 + golden fixtures  
- LLM 情感：**不做前端**；后置后端 L1（P4）

## 原则

1. **判定逻辑归后端，展示逻辑归前端。**  
2. **后端只产出计数（counts），前端只产出比率（rates）。**  
3. 比率不可加 → 自由时间窗必须用 Σm/Σn，禁止对日比率求平均。  
4. 一致性靠：共享规格/纯函数、口径配置后端下发、版本戳（标注/词典）、显式分母（answer_status）。

## 分层

| 层 | 名称 | 责任 |
|----|------|------|
| L0 | Raw | 后端 append-oriented 采集存储 |
| L1 | 单次标注 | 后端必做；幂等；可重跑 |
| L2 | 计数聚合 | 后端纯整数；MVP=API group by |
| L3 | 指标派生 | 前端纯函数；综合分默认不落库 |

## 工程约束（强制精神）

- 分母 = L1 `answer_status` 定义的有效样本  
- 别名/状态枚举/默认权重 → 配置接口，前端不硬编码  
- 综合分不落库（除非带权重版本且与计数分表）  
- 禁止无 fixtures 的双语言同公式放飞  

## 接口

| 类型 | 职责 |
|------|------|
| 明细 | raw + 标注 + 截图 |
| 计数聚合 | group by → counts only |
| 口径配置 | 别名、状态、权重… |

## 落地顺序（与 B 对齐）

| 阶段 | 内容 | B |
|------|------|---|
| P0 | Raw | B3/B5 |
| P1 | 规则 L1 | B4 |
| P2 | 计数 API | B6（2B） |
| P3 | 前端 L3 看板 | 前端阶段 |
| P4 | LLM 标注（情感等） | 后置，后端 |
| P5 | 竞品深对比/告警等 | 更后 |

## 验收精神（摘录）

- 任意时间窗：前端提及率 = 从明细按同一分母重算  
- 分母不等时：周指标 ≠ 日比率算术平均  
- L3 单测入参不接受比率类型
