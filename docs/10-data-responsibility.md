## 一句话

后端负责**抓得到、标得准、数得清（计数）**；  
前端负责**除得出、画得明（比率与综合分）**；  
禁止把日比率存库再平均当周月指标。

## 四层

```text
L0 Raw          后端 · 原始回答/引用/平台/prompt/时间/截图
L1 Annotation   后端 · 单次标注（必做、可重跑、宜带版本）
L2 Counts       后端 · 纯整数计数（MVP=聚合 API；日后可日表物化）
L3 Rates        前端 · 纯函数：只吃 counts → 比率/SoV/综合分/趋势
```

| 层 | 谁 | 存什么 / 算什么 | MVP |
|----|----|-----------------|-----|
| **L0** | 后端 | full_text、citations、platform、prompt、时间、screenshot… | 必做 B3/B5 |
| **L1** | 后端 | 见下方白名单 | 必做 B4（规则） |
| **L2** | 后端 | 有效样本数 n、命中数 m、… **无比率** | 计数 API（2B）；物化后置 |
| **L3** | 前端 | 提及率=m/n、SoV、综合分、曲线 | 正式前端阶段 |

## L1 第一期白名单（仅此）

| 字段意图 | 说明 |
|----------|------|
| `answer_status` | 答案是否有效（分母唯一依据，枚举需写死） |
| 本品是否提到 | 基于别名库 |
| 竞品是否提到 | 对 competitor 列表逐个 |
| `mention_type` | 如 body / citation_only / none |
| 首次位置 | offset 与/或 head·middle·tail bucket |

**明确不做进 L1 MVP：** LLM 情感、角色、幻觉、细粒度属性。

## 情感 / LLM 能否做在前端？

| 做法 | 是否推荐 | 原因 |
|------|----------|------|
| **LLM 情感在前端** | **不推荐** | 要 API Key、费用、限流、延迟；结果难与报表/告警一致；词典与 prompt 版本难统一 |
| **规则/关键词粗情感在前端（L3）** | 可作演示 | 无密钥，但质量差，且与「判定归后端」略冲突 |
| **LLM 情感在后端（L1 后置 P4）** | **推荐路径** | 密钥与成本可控；写入 L1 可版本化重跑；L2 只累加 pos/neu/neg **计数**，前端算占比 |

**结论：** 情感若上 LLM → **后端 L1 后置**；前端只消费情感**计数**做占比/净分。不把 LLM 调用放到浏览器。

## L2 计数（API 至少能支撑）

前端 L3 基础看板至少需要能取到（可 group）：

- 有效运行数 n（仅 `answer_status=有效`）
- 本品命中数 m、Top1/Top3 次数（有 rank 后再加）
- 位置相关可用的和/计数
- 本品提及总数、竞品提及总数（SoV 分母）
- 可选：失败/空回答等质量计数

**禁止** API 直接返回「提及率」「周平均日提及率」作为权威结果。

## 三个接口方向

| 接口 | 返回 |
|------|------|
| 明细 | L0 + L1（下钻、B7 质检） |
| 计数聚合 | **仅 counts**，参数化时间窗/平台/品牌 |
| 口径配置 | 别名规则说明、answer_status 枚举、默认综合分权重等 |

## 公式与一致性（4A）

- L1 / 校验：后端 `packages/metrics`（Python）
- L3：前端 TS 纯函数模块，**入参只接受 counts**
- 同一公式若双端实现 → **golden fixtures** 双边对照
- 综合分：**展示层**，默认不落库；若将来落库必须带权重版本号
