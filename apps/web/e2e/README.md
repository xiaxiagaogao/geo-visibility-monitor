# 端到端测试

238 条单元测试全是 `lib/l3/` 的纯函数。表现层此前完全没有网 ——
改版期间的几个真 bug（`-webkit-box` 把 `<td>` 踢出表格盒模型、出血写法吃掉
56px 内容宽、7 处 className 指向不存在的 CSS 类）全是靠人眼看截图发现的。
交互回归比样式回归更难靠截图发现：点了没反应、展开后没渲染、路由没跟上，
截图上一模一样。这套测试补的是这块。

## ⚠️ 它跑在生产数据上

`next.config.ts` 的 dev rewrites 把 `/v1` 代理到 `https://geo.xg22.top`。
本机没有独立后端，也没有测试库。所以**每个用例都必须只读**。

这条不靠自觉守：`fixtures.ts` 里装了一道路由拦截，**除登录/登出外，
任何非 GET 的 `/v1` 请求一律 abort 并让该用例失败**。
将来谁不小心写了个「点立即运行」，会当场炸掉，而不是默默在线上建了个 job、
花掉额度、且撤不回来。

## 怎么跑

不需要凭据的那档（登录页，5 条）直接跑：

```bash
pnpm --dir apps/web e2e e2e/login.spec.ts
```

需要登录的那档（15 条）要凭据。**凭据只从环境变量来，不进仓库**；
没给的话这些用例**跳过**而不是失败 —— 一个因为没配凭据而常红的套件，
跑几次就没人看了。

用 `read -s` 而不是直接写在命令里，免得密码进 shell 历史：

```bash
read -s -p "密码: " E2E_PASSWORD && export E2E_PASSWORD && export E2E_EMAIL=你的邮箱 && pnpm --dir apps/web e2e
```

跑完记得 `unset E2E_PASSWORD`。

## 建议专门开一个只读账号

用超管账号跑测试，护栏是唯一的防线。建一个 `role=客户` 的账号专供 e2e，
它在**后端**就只能读自己 workspace 下的数据 —— 多一层，且那层不在测试代码里。

## 断言写不变量，不写数字

生产数据每天在变。断言「12 次运行」明天就红了，而那不是回归。
所以断言的是结构与口径不变量，例如：

- 每个大号比率读数旁边**必须有分母**（`m / n`）—— 这是这个产品可信度的来源
- `0%` 出现时同一块里必须有分母佐证 —— 否则分不清「真是 0」还是「算不出来」
- 一页**有且只有一个** h1，且在面板之外
- 竞品必须是「须」不是 polygon 区间带 —— 带会插值出两次运行之间没测过的值
- 点图上第 N 次运行，URL 必须落到**那一次**的 run id

这些恰好也是最该被钉住的东西。

## 两个踩过的坑

1. **控制台守卫要放过未登录时的 401。** `GET /v1/auth/me` 在未登录时返回 401
   是正确行为，但 Chrome 会记一条 console error。只放过 401，其余照旧算失败。
2. **`a[href^="/tasks/"]` 会命中页头的「新建任务 +」**（`/tasks/new`），
   点进去是新建表单，后面的断言会以很难懂的方式失败。必须
   `:not([href$="/new"])`。品牌页同理。
